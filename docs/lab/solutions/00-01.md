# Solutions — Labs 00–01

## 0-A (ethics memo)
Model answer: state ownership (the APK in this course is the owner's own
product), purpose (source recovery + rebuild), scope limits (no live-server
interaction, no redistribution of third-party SDK code found inside, results
stay in the project), jurisdiction note (local RE/interop law), and a date.
Key grading point: *the memo exists and names an authority chain*.

## 0-B (entry count)
`unzip -l` lists **4,863 entries**; many are *directory entries* (e.g.
`assets/bin/Data/`, `res/drawable/`) which are not files. On-disk regular
files under `assets/bin/Data/` number 3,518 — counting methodology differs
(zip entries vs directory tree). Lesson: define your unit of counting.

## 1-A (base64)
`MTI0ODI5NzQwMA==` → `1248297400` (Tapjoy app id — ~1.2e9, ad-network id
space). `MTU5MjY1OTQ0OQ` → `1592659449` (Nexon notice API client id, ~1.6e9).
Both are epoch-second-scale integers (~2015/2020). Difference in *meaning*:
ad SDK identity vs content-platform client id; both vendors chose base64 of a
decimal integer — a common, mildly security-theater convention.

## 1-B (permissions)
INTERNET, VIBRATE, WAKE_LOCK, BILLING, plus `android.hardware.telephony`
feature (not permission — common copy-paste bug in manifests), legacy
`org.apache.http.legacy` library requirement — all consistent with a
2016-era Korean SDK stack. Modern equivalent would drop telephony and add
AD_ID. Most are *SDK artifacts*, not game needs: the game itself needs only
INTERNET (+BILLING).
